## 以后（按需要再排）

- **分享菜单（快捷指令）**：快捷指令放进分享菜单，把链接、文字、截图写进 `pick-nest-data/inbox/<时间>-<随机>.json`（一次分享一个文件，不改主文件）；App 同步时取出来，确认后加入，再删掉这个文件
- **食谱库（先手动录入）**：食谱、食材行；从食谱「加缺的食材」到清单（用 `items.needs` 记来源，同单位才相加）；加食材时联想用到它的食谱；常备品（盐、油、生抽默认不勾）
- **Meal plan**：日历，按日期范围生成要买的东西；改计划时只调整来自计划的那部分数量，不动手动加的
- **AI 导入**（暂缓）：粘贴文案 / 截图 → 云端模型提取 → 确认 → 加入。API key 只存本机、设花费上限。小红书 / 抖音链接很难直接抓（要 cookie 和签名），以粘贴分享文案和截图为主
- **项目（Project）**：木工等项目的材料清单，和食谱共用「来源 → 数量」的机制
- **图片**：IndexedDB 存图，同步到 data 仓库（照 babble 录音的做法：按内容的 sha256 命名、只增不改）
- **多人共用**：按字段合并（每条记录带 `fieldAt`）、勾选更快推送（小的「当前清单」文件 + 打开清单时短轮询）
- 价格记录、周期购买、到店提醒（网页 App 做不了地理围栏，要原生）

## 已定的决定

| 决定 | 原因 |
|---|---|
| 和 babble、房屋账本一样：无构建的网页 App + GitHub 私有仓库同步 | 同步、离线、三种语言、备份恢复都是现成验证过的；不需要账号、服务器和 $99 开发者账号 |
| 不用 Supabase | 免费版一周用得少会暂停；supabase-js 没有离线写入队列；主屏幕网页 App 登录麻烦 |
| 暂不做原生 SwiftUI | 这台 Mac 没装 Xcode；CloudKit 要付费账号；SwiftData 不支持跨 Apple ID 共享；非 Pro 的 iPhone 15 用不了苹果端侧模型 |
| 本机数据先用 localStorage 日志（babble 的 persistence） | V1 数据小；这套写法有测试、有损坏恢复；主屏幕 App 各自有独立的存储。图片以后放 IndexedDB |
| 同一张清单里同名的东西用固定 id | 再买一次时恢复同一条，记录不会越积越多；离线各加一次不会重复 |
| 算 id 时先找同一张清单里同名的记录（没删除的优先），没有才用固定 id，固定 id 被占了才用随机 id | 改名改成同名的、从别的清单移过来的、以前分到随机 id 的，都已经在这张清单上；只看固定 id 那一格会再多出一条 |
| 内容没变的写入不盖新时间 | 预置记录靠 `updatedAt: 0` 表示没人改过；白盖一个新时间，合并时会盖过别的设备上的删除 |
| 版本号单独放在 `src/version.js`（由 `scripts/prepare-release.mjs` 和 `sw.js` 的 `CACHE` 一起写，不要手改） | 启动器要拿它核对 worker 的版本，设置页的「关于」也要显示；`app.js` 不能 import 启动器（那会再启动一次） |
| 本机数据读不出来、存储用不了时不补预置记录 | 恢复页显示「能读出几张清单」，补进去的预置清单会让人以为读到了；修好后再补 |
| 常去的商店按「买的次数」算 | 偶尔换一家买一次不改习惯 |
| V1 不接 AI | 先把手动录入的清单做好用 |
