- **分享菜单（快捷指令）**：快捷指令放进分享菜单，把链接、文字、截图写进 `pick-nest-data/inbox/<时间>-<随机>.json`（一次分享一个文件，不改主文件）；App 同步时取出来，确认后加入，再删掉这个文件

- **图片**：IndexedDB 存图，同步到 data 仓库（照 babble 录音的做法：按内容的 sha256 命名、只增不改；`core/sync.js` 里留了位置，`core/sha256.js` 到时再从 babble 移植）
- **多人共用**：按字段合并（每条记录带 `fieldAt`）、勾选更快推送（小的「当前清单」文件 + 打开清单时短轮询）

## 已定的决定

| 决定 | 原因 |
|---|---|
| 和 babble、房屋账本一样：无构建的网页 App + GitHub 私有仓库同步 | 同步、离线、三种语言、备份恢复都是现成验证过的；不需要账号、服务器和 $99 开发者账号 |
| 不用 Supabase | 免费版一周用得少会暂停；supabase-js 没有离线写入队列；主屏幕网页 App 登录麻烦 |
| 暂不做原生 SwiftUI | 这台 Mac 没装 Xcode；CloudKit 要付费账号；SwiftData 不支持跨 Apple ID 共享；非 Pro 的 iPhone 15 用不了苹果端侧模型 |
| 本机数据先用 localStorage 日志（babble 的 persistence） | V1 数据小；这套写法有测试、有损坏恢复；主屏幕 App 各自有独立的存储。图片以后放 IndexedDB |
| 同一张清单里同名的东西用固定 id | 再买一次时恢复同一条，记录不会越积越多；离线各加一次不会重复 |
| 算 id 时先找同一张清单里同名的记录（没删除的优先），没有才用固定 id，固定 id 被占了用算出来的下一个空位（不用随机 id） | 改名改成同名的、从别的清单移过来的、以前分到随机 id 的，都已经在这张清单上；只看固定 id 那一格会再多出一条。随机 id 的话两台设备离线各加一次，同步后是两条 |
| 合并还是整条取较新的，只有 items、memory 里各自从头建的同一条（`createdAt` 不一样）补上空着的字段 | 新设备、被清掉存储的设备先加了同名的，建的是一条空白的新记录：整条取它会永远丢掉云端那条的备注、链接、价格和习惯；同一条记录照旧整条取较新的，清空的字段不会被旧的补回来 |
| 开着的 App 自己 `registration.update()`（启动后、切回来，最多半小时一次），不 `skipWaiting` | 装好以后 `register()` 不检查新版，主屏幕上的 App 常常只是切回来，不是重新打开：不查的话要冷启动两次才用上新版 |
| 切到后台的直接上传先打断正在跑的一轮，私有检查放宽到 30 分钟 | 页面随时会被挂起：排在一轮拉取后面、或者先问一次仓库，上传多半发不出去；带着 sha 上传，云端变过照样 409 → 合并 |
| 内容没变的写入不盖新时间 | 预置记录靠 `updatedAt: 0` 表示没人改过；白盖一个新时间，合并时会盖过别的设备上的删除 |
| 版本号单独放在 `src/version.js`（由 `scripts/prepare-release.mjs` 和 `sw.js` 的 `CACHE` 一起写，不要手改） | 启动器要拿它核对 worker 的版本，设置页的「关于」也要显示；`app.js` 不能 import 启动器（那会再启动一次） |
| 本机数据读不出来、存储用不了时不补预置记录 | 恢复页显示「能读出几张清单」，补进去的预置清单会让人以为读到了；修好后再补 |
| 常去的商店按「买的次数」算 | 偶尔换一家买一次不改习惯 |
| V1 不接 AI | 先把手动录入的清单做好用 |
| 快速添加的解析宁可不认也不认错：中文数字只在单位前面才算，连着字母的数字（B12、V8）是名字，数量要 0 < q ≤ 9999，认不出就整句当名字 | 认错了会悄悄改掉用户写的名字；没认出来的加进去以后还能在编辑面板里改 |
| 一般清单里光秃秃的数字（前后）都不算数量，要写单位或 x | 「iPhone 15」「100 Years of Solitude」「AA 电池 4」这种名字里的数字很常见；食材清单里「鸡蛋 12」更常见 |
| 再加一次已买 / 已清除的东西：恢复同一条，带着上次的分类、单位、备注，商店按常去的重新定 | 和「同名是同一条记录」一致；商店是「这次」在哪买，习惯以 memory 为准 |
| 快速添加里写了单位也记进 memory；勾上 30 分钟内又取消时把那次购买减回去，隔久了再取消不减 | 下次不写单位也对；点错了又点回来不该改掉常去的商店；又要买了从「已买」点回来，不该把买过的那次抹掉（不然每样东西在每家店最多只算一次） |
| 改成「未分类」也记在 memory（`categorySet`） | 和「没改过」都是 `categoryId: null`，分不开的话分错的分类下次又按对照表猜回来 |
| 移到别的清单时那边已经有同名的：先确认，合并成那一条（恢复成要买），这一条软删除 | 同一张清单里同名的只能有一条（固定 id 的规则） |
| 按分类分组时只给「不在清单默认商店买的」标店名 | 每行都写「Whole Foods」等于没写，例外的「H Mart」反而不显眼；按商店分组时组名就是店 |
| 分组方式、「已买」「以后再说」折没折放在本机（`picknest.local` 的 `view`），不同步 | 手机上按商店、iPad 上按分类都可以；只是显示方式，不是数据 |
| 勾掉、取消勾选都先在原地改样子，约 0.3 秒再挪；连着点几样等最后一下之后一起挪；刚挪了位置的行 0.35 秒内点了不算（减少动态效果时直接挪） | 网页 App 没有震动反馈，马上挪走看不出点没点中；挪的时候手指下面换了一样东西，连点、双击会改掉另一样 |
| 只有点左边的圆圈才勾掉 / 取消（圆圈的按钮占满左边一栏、整行高，≥ 48 px）；点这一行别的地方打开编辑面板，› 只是提示 | 以前点整行就勾，推着车、滚着页面一碰就勾掉了（Chi 的要求）；编辑面板要点「保存」才改，点错了关掉就是 |
| 每一行能左右滑（照 babble）：往右「编辑」，往左「删除」，每一行都一样；滑开只露出按钮，点了按钮才做；「以后再说」只在编辑面板的「状态」里改 | 在店里单手推着车，滑过头、甩一下就删掉太容易误触；按钮露出来再点一下，和删除面板里的一样能撤销。一边一个好记，也和 babble（往左删除、往右收藏）一致（Chi 的要求；以前往左是「编辑」「删除」、往右是「以后再说」/「移回要买」） |
| 清单页的顶栏和快速添加都吸顶 | 长清单滚下去也要能返回、打开「⋯」；主屏幕上的网页 App 没有边缘右滑返回 |
| 首页排顺序用「编辑」里的 ↑↓（44px、读屏念「上移『食材』」），不做拖动 | 手机上拖动容易误触，也不好用读屏操作；清单不多 |
| 「商店」页和商店页不算归档的清单上的东西 | 归档 = 先收起来；收起来的清单不该还在店里催着买 |
| 按商店看时可以只看一张清单（「所有清单 ▾」），「商店」页、每家店、从商店进的购物模式共用本机记住的一个（`picknest.local` 的 `storeFilter`）；那张清单删掉、归档了按所有清单显示，不提示也不改记着的 | 去 Home Depot 只为木工买东西时，别的清单的东西是干扰（Chi 的要求）；每家店各记一个的话换一家又要重选。只是显示方式，和分组方式一样不同步；留着一张看不到的清单只会让每家店都显示成空的 |
| 只看一张清单时「商店」页只列这张清单在那儿有东西的店，下面一句「另外 N 家店在「木工」里没有要买的」 | 选一张清单是要看它要去哪几家；一排 0 会把有东西的那一两家埋在中间。要进别的店换回「所有清单」就是 |
| 清单的图标：画好的线条图标存在 `glyph`，自己写的（emoji、一两个字）存在 `icon`，自己写的显示在前；换图标时两样一起存、另一样清空 | 旧版（v15 和更早的）保存编辑面板时总会交回 `icon` 再截成第一个字：画好的要是也放在 `icon` 里（`i:saw`），旧设备上改个名字图标就变成字母「i」。旧版不认识 `glyph`，原样留着；旧版只会写 `icon`，那就是最后一次换的图标 |
| 归档的商店还有要买的东西时照样出现在「商店」页（标「已归档」） | 归档只是不在选择里出现；已经指定给它的东西不能在哪儿都看不到 |
| 删掉商店 / 分类时不改东西上的 `storeId` / `categoryId`，只是当成「未指定 / 未分类」 | 删除可以撤销（以后还有最近删除）：恢复时东西跟着回来；不用一次改一大批记录（同步时也少冲突） |
| 分类按「用在哪种清单」分三组排顺序，组内的 ↑↓ 只挪这一个（所有分类是一套 `order`） | 两边都用的分类和食材分类会出现在同一张清单上，顺序要是一套；只挪这一个，别的相对顺序不变 |
